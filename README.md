# Lila

نسخهٔ مرجع و قابل ادامهٔ اپ مدیریت اجاره.

## تصمیم فعلی

- **منبع حقیقت داده‌ها:** PostgreSQL در backend؛ نه `localStorage` و نه PIN داخل مرورگر.
- **backend:** FastAPI + SQLAlchemy + Alembic.
- **frontend:** HTML/CSS/JavaScript ماژولار و RTL با PWA.
- **احراز هویت:** نشست سمت سرور و نقش‌های مدیر/مالک.
- **نسخهٔ قدیمی:** `legacy-reference/Lila-app-fixed` فقط برای حفظ ظاهر و امکاناتی است که هنوز باید به نسخهٔ جدید منتقل شوند؛ آن را به‌عنوان نسخهٔ اصلی اجرا نکنید. نسخهٔ ZIP اصلی‌ها در `archive/` آرشیو شده‌اند و نباید به‌عنوان درخت منبع موازی استفاده شوند.

## چرا این نسخه انتخاب شد؟

فایل‌های `Lila-app-fixed.zip`، `Lila-app-fixed (1).zip` و `Lila-app-fixed (2).zip` تقریباً یک برنامهٔ واحد هستند. `Lila-app-fixed.zip` جدیدترین کپی و از نظر ظاهر کامل‌تر است؛ دو فایل `(1)` و `(2)` نیز از نظر بایت دقیقاً یکسان‌اند. بااین‌حال، همهٔ منطق در یک `index.html` حدوداً ۳۳۰ هزار کاراکتری، با ۸۴ رویداد inline و ترکیب هم‌زمان Supabase، `localStorage` و cache مرورگر قرار دارد. این ساختار برای استفادهٔ فوری مناسب است، اما برای ادامهٔ طولانی شکننده است.

آرشیو `Lila-v2-experimental (1).zip` ساختار درست‌تری دارد: دادهٔ پایدار، migration، احراز هویت، نقش‌ها، audit log، محاسبات سمت سرور و frontend جدا. این پروژه از همان به‌عنوان پایه استفاده می‌کند.

## وضعیت مهم

این پروژه هنوز جایگزین فوری نسخهٔ قدیمی نیست. داده‌های واقعی Supabase به PostgreSQL جدید منتقل نشده‌اند و بعضی امکانات پیشرفتهٔ نسخهٔ قدیمی، مانند ادغام تراکنش‌ها، ورود صورت‌حساب بانکی، سطل حذف و جزئیات کامل آرشیو، باید قبل از مهاجرت نهایی به این ساختار اضافه شوند.

تا زمان تکمیل مهاجرت:

1. برای کار روزمره از نسخهٔ فعلی منتشرشدهٔ Supabase استفاده کنید.
2. از `legacy-reference/Lila-app-fixed` به‌عنوان مرجع امکانات و ظاهر استفاده کنید.
3. توسعهٔ بعدی را فقط در `backend/` و `frontend/src/` همین پروژه انجام دهید.
4. قبل از خاموش‌کردن نسخهٔ قدیمی، export و import داده و تست دستگاه دوم انجام شود.

## اجرای محلی

1. `.env.example` را به `.env` کپی کنید و رمزهای نمونه را عوض کنید.
2. با Docker Compose اجرا کنید:

```bash
docker compose up --build
```

3. برنامه روی `http://localhost:8000` باز می‌شود.

برای بررسی فقط ظاهر، بدون دیتابیس، `http://localhost:8080/preview.html` را با یک سرور فایل محلی باز کنید. این پیش‌نمایش از دادهٔ ساختگی استفاده می‌کند و هر بار که ظاهر را تغییر دهم برای بررسی موبایل هم گرفته می‌شود. روند کامل در `docs/UPDATE-WORKFLOW.md` ثبت شده است.
